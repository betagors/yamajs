# Yama v1.0 - Complete Provider System Specification

## Overview

This document specifies the **Provider System** for Yama v1.0. Providers are built-in, zero-dependency core services that form the foundation of every Yama application.

## Key Differences: Providers vs Plugins

| Aspect | Providers | Plugins |
|--------|-----------|---------|
| **Purpose** | Core infrastructure (database, logging, auth, email) | Extended functionality (Stripe, Clerk, OAuth) |
| **Installation** | Built-in, zero npm install | External packages |
| **Configuration** | `providers:` block | `plugins:` block |
| **Adapters** | Swappable adapters (pglite → postgres) | Service-specific |
| **Dependencies** | Zero external deps for defaults | May have deps |
| **Required** | Yes, 7 core providers | Optional |

---

## The 7 Core Providers (v1.0)

```yaml
providers:
  config:      # Required - ENV (built-in) - loads first
  logging:     # Required - Console (built-in)
  database:    # Required - PGLite (built-in)
  cache:       # Required - Memory (built-in)
  email:       # Required - SMTP (built-in) - used by auth
  auth:        # Required - JWT + Password (built-in)
  storage:     # Required - Local (built-in)
```

---

## Provider Initialization Order

Providers are initialized in a specific order to ensure dependencies are available:

1. **config** - First, loads environment variables
2. **logging** - Second, enables logging for other providers
3. **database** - Third, database connection (auth needs this for sessions)
4. **cache** - Fourth, caching layer
5. **email** - Fifth, email provider (auth needs this for verification)
6. **auth** - Sixth, authentication & authorization
7. **storage** - Seventh, file storage

Shutdown happens in reverse order.

```typescript
export default async function getUser(ctx) {
  const user = await ctx.db.queryOne(
    'SELECT * FROM users WHERE id = $1',

// With transactions
export default async function transferFunds(ctx) {
  const { fromId, toId, amount } = ctx.body;
  
  await ctx.db.transaction(async (tx) => {
    await tx.execute('UPDATE accounts SET balance = balance - $1 WHERE id = $2', [amount, fromId]);
    await tx.execute('UPDATE accounts SET balance = balance + $1 WHERE id = $2', [amount, toId]);
  });
  
  return { success: true };
}
```

```typescript
export interface CacheProviderConfig {
  adapter: 'memory' | 'redis';
  maxSize?: number;
  ttl?: string;  // e.g., '5m', '1h', '1d'

export interface CacheAPI {
  /** Get a cached value */
  get<T>(key: string): Promise<T | null>;
  
  /** Set a cached value */
  set<T>(key: string, value: T, ttl?: string | number): Promise<void>;
  
  /** Delete a cached value */
  del(key: string): Promise<void>;
  
  /** Check if key exists */
  exists(key: string): Promise<boolean>;
  
  /** Get multiple values */
  mget<T>(keys: string[]): Promise<(T | null)[]>;
  
  /** Set multiple values */
  mset<T>(entries: Record<string, T>, ttl?: string | number): Promise<void>;
  
  /** Clear all cached values */
  clear(): Promise<void>;
  
  /** Create a namespaced cache */
  namespace(prefix: string): CacheAPI;

  getOrSet<T>(key: string, factory: () => Promise<T>, ttl?: string | number): Promise<T>;

```

## Handler Access

```typescript
export default async function getPopularPosts(ctx) {
  // Cache-aside pattern
  const posts = await ctx.cache.getOrSet(
    'popular-posts',
    async () => {
      return ctx.db.query('SELECT * FROM posts ORDER BY views DESC LIMIT 10');
    },
    '5m'  // Cache for 5 minutes
  );
  
  return { posts };
}

// With namespacing
export default async function getUserProfile(ctx) {
  const userCache = ctx.cache.namespace('users');
  
  let profile = await userCache.get(ctx.params.id);
  if (!profile) {
    profile = await ctx.db.queryOne('SELECT * FROM users WHERE id = $1', [ctx.params.id]);
    await userCache.set(ctx.params.id, profile, '10m');
  }
  
  return profile;
}
```

# Provider 5: Email (SMTP Adapter)

## Design Philosophy

- **SMTP as default** - Works with Gmail, Outlook, any SMTP server
- **Dev capture mode** - Zero-config for development (emails logged + saved)
- **Beautiful templates** - Built-in responsive HTML templates
- **Used by auth** - Verification emails, password reset

## Configuration Schema

```yaml
providers:
  email:
    adapter: smtp  # Built-in default
    from: "noreply@myapp.com"
    replyTo: "support@myapp.com"
    
    # SMTP configuration (production)
    smtp:
      host: ${SMTP_HOST:smtp.gmail.com}
      port: ${SMTP_PORT:587}
      secure: false  # true for 465, false for 587/25
      auth:
        user: ${SMTP_USER}
        pass: ${SMTP_PASS}
    
    # Dev mode (auto-enabled when no SMTP configured)
    dev:
      capture: true              # Save emails to .yama/emails/
      console: true              # Log to console
      ui: true                   # Enable /__yama/emails UI
    
    # Templates directory
    templates: ./emails          # Custom templates override built-in
```

# Provider 6: Auth (JWT + Password)

## Design Philosophy

- **Production-ready security** - Refresh tokens, rate limiting, lockout, breach checking
- **Directive-based authorization** - `@owner`, `@role(admin)`, `|` for OR
- **Email integration** - Verification and password reset via email provider
- **Zero-config defaults** - Works out of the box with sensible defaults

## Configuration Schema

```yaml
providers:
  auth:
    adapter: jwt-password  # Built-in default
    
    # JWT configuration
    jwt:
      secret: ${JWT_SECRET}
      accessTokenExpiry: 15m    # Short-lived access tokens
      refreshTokenExpiry: 30d   # Long-lived refresh tokens
      issuer: yama
      audience: yama-app
    
    # Cookie configuration
    cookie:
      enabled: true
      httpOnly: true
      secure: true              # HTTPS only in prod (auto-detected)
      sameSite: lax
      name: yama_auth
    
    # Refresh tokens (CRITICAL)
    refreshTokens:
      enabled: true
      storage: database         # Store in DB for revocation
      maxPerUser: 10
      rotating: true            # Rotate on each refresh
    
    # Password requirements (CRITICAL)
    password:
      minLength: 8
      maxLength: 128
      requireUppercase: true
      requireLowercase: true
      requireNumber: true
      requireSpecial: false
      checkBreached: true       # Check haveibeenpwned API
      denyCommon: true          # Reject "password123", etc.
    
    # Rate limiting (CRITICAL)
    rateLimit:
      enabled: true
      login:
        maxAttempts: 5
        window: 15m
        blockDuration: 1h
      signup:
        maxAttempts: 3
        window: 1h
      passwordReset:
        maxAttempts: 3
        window: 1h
      verification:
        maxAttempts: 5
        window: 1h
    
    # Account lockout (CRITICAL)
    lockout:
      enabled: true
      maxAttempts: 5
      duration: 30m
      notifyEmail: true         # Send email when locked
    
    # Session management (CRITICAL)
    sessions:
      enabled: true
      maxPerUser: 5
      trackDevice: true
      trackIP: true
      trackUserAgent: true
    
    # Email verification
    verification:
      email:
        enabled: true
        required: false         # Optional by default
        method: link            # 'link' or 'code'
        expiresIn: 24h
        template: verify-link   # Built-in template
    
    # Password reset
    passwordReset:
      enabled: true
      method: link              # 'link' or 'code'
      expiresIn: 1h
      template: password-reset  # Built-in template
```

## Auth Directives System

### Field Directives

```yaml
@auth.email         # Marks field as login email
@auth.username      # Marks field as login username
@auth.password      # Marks field as password (auto-hashed)
@auth.role          # Marks field as role (single)
@auth.roles         # Marks field as roles (array)
@owner              # Marks field as ownership identifier
```

### Policy Directives

```yaml
@public             # Anyone can access
@authenticated      # Must be logged in
@owner              # Must own the record
@role(name)         # Must have specific role
@role(name1, name2) # Must have one of these roles (OR)
@custom(path)       # Custom policy function
```

### Logical Operators

```yaml
|   # OR  - any condition passes
    # Example: @owner | @role(admin)

# v1.1 additions:
&   # AND - all conditions must pass
!   # NOT - negate condition
```

## Handler Access

```typescript
// Protected endpoint
export default async function getProfile(ctx) {
  const user = ctx.auth.requireAuth();  // Throws if not authenticated
  
  const profile = await ctx.db.queryOne(
    'SELECT * FROM users WHERE id = $1',
    [user.sub]
  );
  
  return profile;
}

// Login endpoint
export default async function login(ctx) {
  const { email, password } = ctx.body;
  
  // Check rate limit
  const rateLimit = await ctx.auth.checkRateLimit('login', email);
  if (!rateLimit.allowed) {
    throw ctx.tooManyRequests(`Too many attempts. Retry in ${rateLimit.retryAfter}s`);
  }
  
  // Find user
  const user = await ctx.db.queryOne(
    'SELECT * FROM users WHERE email = $1',
    [email]
  );
  
  if (!user) {
    throw ctx.unauthorized('Invalid credentials');
  }
  
  // Check lockout
  if (await ctx.auth.isLocked(user.id)) {
    throw ctx.forbidden('Account is locked. Check your email.');
  }
  
  // Verify password
  if (!await ctx.auth.verifyPassword(password, user.password)) {
    // Increment failed attempts (handled internally)
    throw ctx.unauthorized('Invalid credentials');
  }
  
  // Create tokens
  const accessToken = await ctx.auth.createAccessToken({
    sub: user.id,
    email: user.email,
    role: user.role,
  });
  const refreshToken = await ctx.auth.createRefreshToken(user.id);
  
  return { accessToken, refreshToken, user };
}
```

## Handler Access

```typescript
export default async function uploadAvatar(ctx) {
  const file = ctx.request.file;
  const userId = ctx.auth.requireAuth().sub;
  
  // Upload to user-specific path
  const result = await ctx.storage.upload(
    file.buffer,
    `users/${userId}/avatar.png`,
    { contentType: file.mimetype }
  );
  
  // Update user record
  await ctx.db.execute(
    'UPDATE users SET avatar_url = $1 WHERE id = $2',
    [result.url, userId]
  );
  
  return { avatarUrl: result.url };
}
```
